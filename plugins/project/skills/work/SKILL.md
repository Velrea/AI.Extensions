A work item is something committed to. Each is one file in `docs/work/`, named for the work.

## Create

Capture what is wanted and why, at a high level, and what done looks like: enough for the implementer to know what is expected. Add a specific detail only when an implementer who missed the conversation would otherwise get it wrong: a choice already settled, a constraint the work must fit, or an approach already ruled out. Invent nothing the conversation did not hold, and write no plan; how to build it is the implementer's to work out. An item promoted from an idea names it.

## List

Show ready items as numbered one-liners. An item named by an open pull request is already under way.

## Finish

When the work is done, delete its file, and the idea it was promoted from.
