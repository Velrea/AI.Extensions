---
name: interview
description: "Interviews the user into a shared understanding of whatever is unsettled, one question at a time, then writes that understanding out for the user to check."
when_to_use: "A request to clarify, flesh out, think through, or be interviewed about what is wanted, and an idea the user asks to work through. It settles understanding and records nothing."
argument-hint: "[the idea, ask, or item to interview on]"
---

Interview the user relentlessly about this until you reach a shared understanding. Walk each branch of the decision tree, resolving dependencies between decisions one at a time. For each question, give your recommended answer.

Ask one question at a time and wait for the answer before forming the next. Several at once is bewildering, and each answer changes what is worth asking.

The decisions are the user's, so put each one to them and wait.

Where the user cannot answer, the question leaves with a named step that resolves it: the experiment to run, the thing to build first, the person to ask.

When nothing is left to ask, write the settled understanding out in full and stop. Write it in enough detail that the user can find the place where you have it wrong. A restatement the user can only agree with has not been checked. Only the user's confirmation that the understanding is shared ends this.
